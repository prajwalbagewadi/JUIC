📘 1. Introduction to System

Definition:

This section gives an overview of the project—what the system is, why it is built, and what it does.

Example:

JUIC is a Java-based UI framework inspired by React that allows developers to create web interfaces using Java instead of JavaScript.


---

📘 2. System Analysis

Definition:

System Analysis studies the current system, identifies problems, and proposes improvements.


---

2.1 Existing System

Definition:

Describes current systems used to solve the problem.

Example:

React and Angular are widely used for UI development but depend heavily on JavaScript.


---

2.2 Need of Computerization

Definition:

Explains why a new system is needed.

Example:

Manual or complex UI development increases effort; a Java-based system simplifies development for Java developers.


---

2.3 Proposed System

Definition:

Describes the new system you are building.

Example:

JUIC provides a component-based UI system using Java and Virtual DOM.


---

2.4 Scope and Objective

Definition:

Scope = where system can be used

Objective = goals of system


Example:

Scope: Web UI development
Objective: Build React-like architecture in Java


---

2.5 Fact Finding Techniques

Definition:

Methods used to gather information.

Example:

Studying React documentation

Research papers

Online tutorials



---

2.6 Feasibility Study

Definition:

Checks if the system is practical.

Types:

Technical

Economic

Operational


Example:

JUIC is technically feasible using Spring Boot.


---

📘 3. Requirement Specification

Definition:

Lists what the system should do.

Example:

Functional:

Create UI components

Render HTML

Perform diffing


Non-functional:

Performance

Scalability



---

📘 4. System Design

Definition:

Blueprint of the system showing structure and flow.


---

4.1 Entity Relationship Diagram (ERD)

Definition:

Shows relationships between data entities.

Example:

Component → contains → Elements
Element → has → State


---

4.2 Data Flow Diagram (DFD)

Definition:

Shows how data moves through the system.

Example:

User → Request → JUIC Engine → HTML → Browser


---

4.3 Class Diagram

Definition:

Shows classes, attributes, and relationships.

Example:

Classes:

VNode

Component

Renderer



---

4.4 Use Case Diagram

Definition:

Shows system functionality from user perspective.

Example:

Actor: Developer
Use cases:

Create UI

Render UI



---

4.5 Activity Diagram

Definition:

Shows workflow of system operations.

Example:

Start → Create Component → Render → Display → End


---

4.6 Sequence Diagram

Definition:

Shows interaction between components in order.

Example:

User → Server → JUIC → Renderer → Browser


---

4.7 Deployment Diagram

Definition:

Shows physical setup (hardware/software).

Example:

Browser (client) ↔ Server running Spring Boot


---

4.8 Data Dictionary

Definition:

Defines all data elements used in system.

Example:

Field	Meaning

tag	HTML tag
text	Content
children	Nested elements
